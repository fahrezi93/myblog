Visual Studio Code (VS Code) adalah editor kode paling populer dan sukses di dunia modern. Lengkap, kaya fitur, memiliki jutaan ekstensi, dan didukung oleh raksasa Microsoft.

Namun, jika Anda mengamati komunitas *senior engineer*, *systems programmer*, dan kreator open-source belakangan ini, ada satu fenomena yang tidak terbantahkan: **semakin banyak developer berpengalaman yang memutuskan meninggalkan editor grafis konvensional dan berhijrah penuh ke Neovim.**

Bagi orang luar, ini sering kali terlihat aneh atau bahkan dianggap sekadar elitisme: *mengapa ada orang yang rela menghabiskan waktu berhari-hari belajar kombinasi tombol keyboard yang tidak lazim hanya demi mengetik kode di dalam terminal hitam yang tampak kuno?*

Jawabannya bukan tentang nostalgia, melainkan tentang **ergonomi berpikir, penghapusan distraksi, dan pencapaian kondisi Flow State.**

---

## 1. Mouse adalah Penghambat Arus Pikir (The Mouse Bottleneck)

Dalam psikologi kognitif, kondisi di mana seseorang tenggelam sepenuhnya dalam pekerjaan kreatif dengan konsentrasi tanpa celah disebut sebagai **Flow State**. 

Setiap kali Anda sedang asyik memikirkan alur logika yang rumit, lalu tangan Anda harus melepaskan keyboard, meraih mouse, menggeser kursor ke tab file lain, mengklik baris tertentu, lalu memindahkan tangan kembali ke tombol ketik—momentum mental tersebut terinterupsi sejenak. Mungkin hanya butuh waktu 1.5 detik, tetapi terjadi puluhan kali dalam satu jam.

Neovim dibangun di atas prinsip **Modal Editing**:
*   **Normal Mode:** Mode default untuk bernavigasi dan memanipulasi teks layaknya komandan.
*   **Insert Mode:** Mode khusus saat Anda benar-benar perlu mengetik kata baru.
*   **Visual Mode:** Mode untuk memblok dan menyorot area teks.

Yang membuat modal editing begitu adiktif adalah karena perintahnya tersusun seperti **tata bahasa (*grammar*)**:
*   `d` (delete) + `i` (inside) + `"` (quotes) = Hapus teks di dalam tanda kutip secara instan.
*   `c` (change) + `a` (around) + `p` (paragraph) = Hapus satu paragraf utuh dan langsung masuk mode ketik baru.
*   `y` (yank/copy) + `i` (inside) + `(` (parenthesis) = Salin parameter di dalam kurung fungsi.

Setelah memori otot (*muscle memory*) terbentuk, jemari Anda mengedit kode dengan kecepatan yang sama persis dengan kecepatan pikiran Anda merumuskan solusi, tanpa pernah meninggalkan deretan tombol *home row*.

---

## 2. Ringan, Efisien, dan Respon Instan

Sebagian besar editor modern dibangun di atas kerangka kerja **Electron** (yang pada dasarnya adalah browser web Chromium lengkap yang dibungkus menjadi aplikasi desktop). Di proyek monorepo dengan ratusan ribu baris kode dan puluhan ekstensi aktif, tidak jarang editor tersebut menyedot memori RAM hingga 2 GB – 4 GB dan mulai terasa lambat saat berpindah file.

Sebaliknya, Neovim adalah program biner native berbasis C dan **Lua**. 
- Membuka Neovim memakan waktu kurang dari **20 milidetik**.
- Penggunaan memori RAM saat proyek aktif sering kali berada di bawah **150 Megabyte**.
- Tidak ada jeda input (*input latency*); setiap ketukan terasa tajam dan instan.

Bagi mereka yang terbiasa bekerja di server remote via SSH, pengalaman menggunakan Neovim di remote server terasa sama persis ringannya dengan bekerja di mesin lokal.

---

## 3. Ekosistem Lua yang Membawa Fitur Modern IDE

Dulu, Vim klasik terkenal sulit dikonfigurasi karena menggunakan bahasa kuno *Vimscript*. Namun, kebangkitan Neovim dipicu oleh keputusan revolusioner untuk mengadopsi **Lua** sebagai bahasa konfigurasi dan scripting inti.

Hasilnya adalah ledakan ribuan plugin modern yang mengubah Neovim menjadi IDE kelas atas tanpa mengorbankan kecepatannya:
1. **Built-in Language Server Protocol (LSP):** Dukungan autocomplete cerdas, refactoring, lompat ke definisi fungsi, dan pemeriksaan error TypeScript/Rust yang setara dengan VS Code.
2. **Treesitter:** Parser sintaksis berbasis pohon AST yang menghadirkan penyorotan warna kode (*syntax highlighting*) yang sangat akurat dan navigasi struktural cerdas.
3. **Telescope:** *Fuzzy finder* visual berkecepatan tinggi untuk mencari file, simbol fungsi, atau riwayat git dalam pecahan detik.

## Apakah Anda Harus Pindah ke Neovim?

Neovim tentu bukan untuk semua orang. Kurva pembelajarannya di minggu pertama terasa terjal dan membutuhkan komitmen waktu. 

Namun, berkat hadirnya distribusi siap pakai (*starter distros*) yang terkonfigurasi sangat elegan seperti **LazyVim**, **AstroNvim**, dan **NvChad**, Anda tidak perlu lagi menyusun konfigurasi dari nol selama berminggu-minggu. Anda bisa langsung menikmati lingkungan kerja yang indah, modern, dan fungsional sejak menit pertama pemasangan.

Jika Anda menghabiskan 8 jam sehari di depan editor kode untuk mencari nafkah, meluangkan waktu untuk berinvestasi pada alat kerja yang paling ergonomis, cepat, dan terbebas dari distraksi adalah salah satu keputusan terbaik yang bisa Anda buat untuk perjalanan karier teknis Anda.
